# Conversation ownership and read positions

The customer ID remains the thread ID. Existing messaging-read permission controls access. Owners and managers can assign or clear responsibility. Other eligible messaging staff can claim an available conversation and return their own conversation to the shared queue. An eligible assignee is a current, active, accepted member with messaging permissions in the same business. An inactive assignment is visible as unassigned and its history remains available. Each effective assignment change advances the revision and records the authenticated actor and both assignees. Revision conflicts fence simultaneous edits.

Assignment records responsibility inside the shared staff inbox. Existing message read, reply, media and assistant takeover capabilities remain the authorization boundary. Case assignments keep their own workflow permissions. The thread links only the case records the actor can open.

Read state is per authenticated account within a business. The owner has one position and each staff ID has its own. Assignment and reading are independent. Mark read acknowledges the committed inbound position supplied in the current workspace response. An explicit mark unread flags that thread for the reader without rewinding their acknowledged position. The delivery role lacks inbox access. Counts and list filters share this definition. An assistant flag separately indicates conversation work that needs a reply.

PostgreSQL increments the conversation position for each committed inbound message. Existing inbound history is counted on migration. WhatsApp timestamps still sort history. A unique new message with an earlier provider timestamp increases unread work, while duplicate ingress leaves the position unchanged. The row counter is updated inside the message write transaction and serializes committed inbound positions within each conversation. A stale mark-read request can only acknowledge its observed position. A separate read-state revision protects a newer explicit unread action. Opening or refreshing a conversation has no implicit read side effect.

Assignment and read writes lock the current business, check scoped staff membership inside the transaction and check the current conversation state. Assignment changes use the existing authenticated SSE stream for an invalidation event. Read positions remain private. Polling and authenticated queries reconcile status on refresh, reconnect and other devices.
