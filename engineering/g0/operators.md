# G0 operator capability assessment

These labels describe the disposition of current code for G1. **RETAIN** preserves an implementation, **REFACTOR** keeps the capability and repairs its boundary, **REPLACE** supersedes a mechanism, **RETIRE** removes a redundant or dormant surface after checking dependencies and data, and **MISSING** marks a capability absent from the audited paths.

## Operator paths and gaps

| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

[Assistant](../../apps/api/src/services/assistant/index.ts) can create a pending clarification, resolve catalogue items or create a pending order. An order may wait for clarification, review, confirmation, delivery details or payment. | Loss before classification, ambiguous duplicate creation after retries, and claims outside authoritative evidence. ## Feature disposition

| Existing capability                                                           | Disposition | Why and next action                                                                                                                                                                 |
| ----------------------------------------------------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React dashboard, navigation and query/SSE infrastructure                      | RETAIN      | One existing owner interface. Add workflow status into its current surfaces.                                                                                                        |
| Auth, OTP, tenant context and capability matrix                               | RETAIN      | Existing primitives for trusted actions. Add negative and role/object-specific tests at the entry points that bypass them.                                                          |
| WhatsApp account linking, token encryption, raw HMAC and template policy      | RETAIN      | Useful existing tenant-specific integrations. Live verification remains open.                                                                                                       |
| Redis marker as the inbound acknowledgement authority                         | REPLACE     | A successful HTTP reply can hide lost queue work. Persist accepted supported events and recover using BullMQ.                                                                       |
| BullMQ workers, deterministic job IDs and dead letter queue                   | REFACTOR    | Preserve execution and retry mechanisms. Make durable receipt/effect state, replay and owner-visible recovery authoritative.                                                        |
| Intent, evidence construction, prompt fencing and draft review                | RETAIN      | Reuse tested interpretation and draft paths.                                                                                                                                        |
| Autonomous bypass for material unverified claims                              | REPLACE     | Apply an invariant that binds commitments to trusted facts in every mode. Preserve claim-free auto-replies where permitted.                                                         |
| Manual orders, catalogue/quantity tiers, stock tracking and order transitions | RETAIN      | Use the existing services and transactions. Add crash/replay coverage at assistant and shipment handoffs.                                                                           |
| Enquiry-led pending orders, delivery capture and assistant order conversion   | REFACTOR    | Preserve owner controls and clarification. Add durable, idempotent effect boundaries and review reasons.                                                                            |
| Services, resource slots and appointments                                     | RETAIN      | Reuse availability checks and the database conflict constraint.                                                                                                                     |
| Lead follow-up, reminders and rescheduling workflow                           | MISSING     | Add persistent lead/booking work with owner-visible next actions after the G1 reliability gates.                                                                                    |
| Payment confidence tiers, screenshot review, manual money and receipts        | REFACTOR    | Preserve useful confidence semantics. Enforce customer/order alignment, transactional totals and auditable outcomes.                                                                |
| Paystack merchant links and subscription webhooks                             | REFACTOR    | Add durable receipt, retry-safe settlement and reconciliation. Preserve the merchant/subscription separation.                                                                       |
| Numbered invoice lifecycle                                                    | MISSING     | Payment links and receipts are already present. Add invoice issuance and state only after the ledger is safe.                                                                       |
| Dispatch, proof and delivered endpoints                                       | REFACTOR    | Apply assignment scope and transactional shipment/order transitions.                                                                                                                |
| Conversations, review queue, customer history, VIP/blocked flags and segments | RETAIN      | Reuse current inbox and customer interface for care work.                                                                                                                           |
| Provider status callbacks and case/follow-up lifecycle                        | MISSING     | The webhook types include status fields. A persisted delivery/status consumer and case workflow were not found in the traced paths.                                                 |
| Dormant broadcast schema                                                      | RETIRE      | A schema model exists without a traced route, worker or owner UI. Keep stored data and schema until an explicit compatibility and usage check. Omit from the initial operator plan. |
| Shared durable workflow outcome and operator task view                        | MISSING     | Establish receipt/effect state conventions in G1. Extend the existing inbox/dashboard once states are reliable.                                                                     |
