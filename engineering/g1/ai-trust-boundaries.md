# G1-05 source inventory and trust boundaries

The clean baseline is `b86b939378a151795c934aacb7bed394b5330a5d`, including the G1-03 verification commit. G1-05 starts on `codex/g1-05-evidence-gated-ai`. The tracked milestone, G0 operator assessment and ADR 0001 are available. The separately named Codex Prompt Book was unavailable in the worktree and supplied attachments.

| Baseline path | Authority gap and enforcement point |
| --- | --- |
| [Message processor](../../apps/api/src/workers/message-processor.worker.ts) → [intent worker](../../apps/api/src/workers/intent-classifier.worker.ts) | The first classifier can be a model. Its label can select legacy order creation or templates, and `processed` precedes the effect. Validate queue identity against the inbound row and prevent model refusal or provider failure from falling through to order or commitment templates. |
| [Context builder](../../apps/api/src/services/assistant/context-builder.ts), [quote resolution](../../apps/api/src/services/assistant/status-context.ts), [prompt](../../apps/api/src/services/assistant/prompt.ts) | Catalogue candidates and open orders are locally scoped. Check message and customer identity before retrieval, and enforce same-customer scope for quoted conversation rows. Customer messages, quotes, media descriptions, catalogue prose, owner examples and policy notes can contain instructions. They are data in model input. |
| [Assistant client](../../apps/api/src/services/intent/assistant-client.ts), [decision schema](../../apps/api/src/services/assistant/decision.ts), [router](../../apps/api/src/services/assistant/router.ts) | Model citations and the amount allowlist only check that a row or number exists somewhere in the snapshot. AUTONOMOUS waives failures. A real price cited against the wrong item, a fabricated prose confirmation and an arbitrary nonnumeric promise are possible. Render supported commitments from verified fields and use bounded server-authored conversational responses. |
| [Assistant orchestrator](../../apps/api/src/services/assistant/index.ts), [orders](../../apps/api/src/modules/orders/orders.service.ts), [bookings](../../apps/api/src/modules/bookings/bookings.service.ts) | The order path acts even after a draft verdict, trusts model quantities, and creates then links in separate writes. The booking path can reserve a verified slot based on model output without independently checking the customer asked for that slot. Require customer request evidence and revalidate the proposed effect in the business service. |
| [Checkout](../../apps/api/src/services/assistant/autonomous-checkout.ts), [delivery capture](../../apps/api/src/services/assistant/delivery-flow.ts), [notifications](../../apps/api/src/services/notifications/customer-notifications.ts) | A model PAYMENT label can raise a link despite a refused reply. Delivery capture is deterministic and can produce an independent checkout. Verify eligible customer/order and current outstanding balance at the payment-link service. Keep status and delivery changes in their established domain workflows. |
| [Inbox approval](../../apps/api/src/modules/messages/messages.service.ts), [HTTP capability](../../apps/api/src/modules/messages/messages.route.ts), [dashboard editor](../../apps/web/src/components/messages/ReplyEditor.tsx) | A saved draft can be submitted as dashboard text. Review must check the draft policy and evidence again, including drafts from the prior version. Preserve the separately authored human reply route and record approved, rejected or waiting outcomes. |
| [Status template](../../apps/api/src/services/notifications/customer-notifications.ts), [vision context](../../apps/api/src/services/assistant/describe-image.ts), [insights worker](../../apps/api/src/workers/insights.worker.ts) | Status facts must come from the same customer's order. Vision descriptions are untrusted model inputs. Daily insight text is owner-facing and has no customer-send or business mutation authority. |
