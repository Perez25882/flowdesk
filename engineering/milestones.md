## Exact first assignment for approval

**G1-01 — Persist and recover signed WhatsApp text events before acknowledgement.**

**Status** Founder approved the verified local scope on 2026-11-11. Final code `7fa5465` passed all 15 receipt cases in each of three independent runs, plus 20 legacy tests and a seeded migration upgrade. See the [verification record](g1/verification.md#final-sign-off-verification--2026-11-10) and [workflow and recovery runbook](g1/whatsapp-text-ingress.md).

Start from the G0 baseline on a dedicated branch. Use the existing Fastify route, Prisma/Postgres, BullMQ/Redis, phone-number routing and worker. Add an additive receipt migration and a small dispatcher/recovery path for authenticated inbound WhatsApp **text**. The receipt is keyed by provider, phone-number identity and message ID. Store only the normalized inputs the worker needs and bound retention and retries. A successful response means the supported event is durable or a durable receipt for the same delivery already exists. A failed durable write produces a retryable response.

Persist a waiting state for queue or mapping dependencies, a recoverable failure reason after bounded attempts, and completion evidence when the message is attached to the correct customer and handed to classification. Make dispatch and worker recovery safe across restarts with deterministic job identity and atomic claims. Document the migration, replay command or runbook, retention rules, safe disable/rollback path, and how an operator finds a stuck receipt. Preserve inbound bytes for signature validation and preserve existing behavior of unrelated routes and event types. Scope G1-01 to ingress and classification handoff. G1-06 covers other inbound events, and G1-07 covers downstream commercial idempotency.

**Dependencies** Founder approval, current Postgres/Redis and the local synthetic test harness. G1-00 may proceed independently after approval.

| Acceptance test              | Expected behavior                                                                                                                                                                                                                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Signature and normal ingress | Invalid signature yields 401 with no receipt/job. A signed supported event persists one receipt before 200, then creates one tenant/customer message and hands it to classification.                                                                                                                        |
| Storage or queue failure     | Forced receipt failure yields retryable non-2xx. A committed receipt survives a forced queue failure, remains waiting, and progresses after Redis recovers without a second provider delivery.                                                                                                              |
| Crash and replay             | Kill/restart between receipt commit and enqueue, and between enqueue and receipt state update. A retry or dispatcher recovers one effective handoff. Concurrent duplicate deliveries and retries after job eviction do not recreate a completed handoff.                                                    |
| Batch and tenant isolation   | A valid text item survives a malformed sibling. Unknown/temporarily inactive phone IDs are explicitly waiting or recoverably failed. A collision from a different phone-number identity cannot mutate another tenant's message or trigger its classification. Existing accepted legacy paths are exercised. |
| Operational evidence         | Recovery is tenant-scoped, reason-coded, bounded and documented. Test an empty migration and representative synthetic upgrade. Execute build, typecheck, lint, Vitest and the synthetic smoke path, reporting any unchanged baseline failures separately.                                                   |

Deliver a reviewable code and documentation diff with the real Postgres/BullMQ acceptance tests. Founder approval covers this assignment only.
